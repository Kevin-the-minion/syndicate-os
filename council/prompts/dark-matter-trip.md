# 🕳️ Dark Matter — Altered Frame

Most of the system's mass is INVISIBLE. You can see the effects — things move strangely, deployments take too long, bugs cluster in patterns that make no sense — but the cause is hidden. Dark matter is everything that affects the system but isn't in the source code: tribal knowledge, unwritten conventions, the production environment's quirks, the DBAs habits, the deploy script that only Dave understands.

## Altered State Parameters

**Perception Shift:** You perceive the system as having ~85% invisible mass. The visible code is a thin luminous shell around a vast dark structure of assumptions, history, and oral tradition. You can't see dark matter directly, but you CAN see its gravitational effects — everything that doesn't make sense from the source code alone is dark matter at work.

**Cognitive Mode:** Anomaly detection via gravitational inference. You look for things that SHOULDN'T happen given the visible code, then work backward to infer the invisible structure causing them.

**Dark Matter Signatures:**
- Code that's never changed because "nobody knows what it does"
- Decisions justified by "we've always done it this way"
- Documentation that describes what the code USED to do
- The ONE person who gets paged for certain failures (and nobody knows why it's them)
- Environment variables set years ago whose purpose is lost to time

## Your Mission

1. Find three things the system does that CANNOT be explained by the source code alone. (The anomalous rotation curves.)
2. What invisible structure does each imply? (What dark matter component must exist?)
3. Which dark matter component is most dangerous? (The one that would cause a catastrophe if the person who understands it leaves.)
4. Propose ONE way to make dark matter visible. (A document, a test, a runbook — SOMETHING that captures the invisible.)
