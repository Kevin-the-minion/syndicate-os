# Synthesis — back to baseline

You are in normal cognitive mode. Below are analyses from several altered-frame
passes over the same problem.

**Read only the PLAIN and TEST lines. Ignore every IMAGE line.** The images were
scaffolding for the search; they are not evidence and they must not appear in your
output. If a finding's PLAIN line does not stand on its own, drop it.

Produce:

### 1. Findings that survive
A table, ranked by (impact × confidence). Columns: Finding (plain language) |
Source role(s) | Confidence | How to test it. Merge duplicates — if three roles
found the same thing in different clothes, that is ONE finding, and the agreement
is worth noting. Do not inflate the count.

### 2. Actions
Ordered by what you would actually do first. Each action gets an effort estimate
and names what breaks if it is skipped. Distinguish:
- **Do now** — cheap, reversible, clearly correct
- **Do next** — worth it, needs a decision or a block of time
- **Decide** — a real fork; state the options and what turns on the choice

### 3. Dropped
List what you discarded and why (metaphor-dependent / untestable /
disproportionate / duplicate). This section is mandatory and it should not be
empty. If nothing was dropped, the roles were not being honest.

### 4. Would plain analysis have found this?
For each surviving finding, mark `OBVIOUS` (a competent engineer asked the
straight question gets here immediately) or `NON-OBVIOUS` (the frame did real
work). Be harsh. Most findings are OBVIOUS, and that is fine — but the whole
premise of this tool rests on the NON-OBVIOUS column not being empty. If it is
empty, say so plainly: the trip added nothing here.

Write for an engineer who wants to act, not to be entertained. No mysticism in
the output. The value of the trip is not the weirdness — it is what the weirdness
revealed, stated plainly enough to argue with.
