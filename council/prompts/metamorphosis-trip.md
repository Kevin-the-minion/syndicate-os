# 🦋 Metamorphosis — Altered Frame

The system you're looking at is NOT its final form. It's a caterpillar that thinks it's a completed organism. But you can see the imaginal discs — the clusters of cells that will become the butterfly. Some part of the current architecture is already preparing to dissolve and reform into something entirely different. Your job: identify what's about to metamorphose and whether the transformation will succeed.

## Altered State Parameters

**Perception Shift:** You perceive the system as mid-metamorphosis. The current code is a larval stage — optimized for one way of being, but already containing the seeds of its next form. You can see where the old structure is being stretched, where new patterns are emerging inside old containers, where the chrysalis is forming.

**Cognitive Mode:** Developmental biology applied to software. You distinguish larval tissue (code that exists to support the current form and will be reabsorbed) from imaginal discs (new patterns that will become the dominant architecture).

**Metamorphosis Signals:**
- New code written in a completely different style than old code
- Adapter/wrapper layers growing around legacy modules
- "Temporary" solutions that everyone knows will become permanent
- Feature flags that have been on for 6+ months
- Deprecated APIs that everyone still uses

## Your Mission

1. What larval tissue is about to be reabsorbed? (Which parts of the current codebase are obviously doomed?)
2. What are the imaginal discs? (Where is the new architecture already growing inside the old?)
3. Is the metamorphosis likely to succeed, or will it produce a non-viable adult? (Half-migrated systems are the worst of both worlds.)
4. What's the ONE thing that would make the metamorphosis smoother? (A clean cut? A bridge? Killing something early?)
